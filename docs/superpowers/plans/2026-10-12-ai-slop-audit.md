## 0. 为什么必须先准备

审计面：**372 个受版本控制的非二进制/非锁文件，约 53.9k 行**。把"全面检查"直接执行成"读一遍代码"会有两个必然结果：产出主观意见而非可复核结论；在大范围下中途丢失上下文、无法续跑。

所以准备只需要解决三件事：**定义**（什么叫 slop）、**切块**（怎么枚举与续跑）、**证据**（什么样的话才允许说出口）。

## 1. 什么叫 AI Slop：可判定定义

> **一段代码或文档，如果删掉它不会损害任何行为、契约或证据，而它的存在又会让读者以为有信息量，那它就是 slop。**

两个要点：

1. **slop 不是"写得丑"**，而是**伪装成有信息量**。所以判断标准不是风格偏好，而是"删掉它，谁受损？"——答不出受损方的，才可能是 slop。
2. **必须区分"多余"与"冗余但必需"**。本项目大量防御性代码是安全边界的硬要求（见第 3 节禁止标记清单）。把必需校验报成 slop，会造成真实伤害。

因此每条结论都要能回答：命中的判据编号、删掉谁受损、如何复核。

## 2. 分类法与严重度

| 编号 | 类别 | 典型形态 |
| --- | --- | --- |
| **A** | 空洞或失真注释 | 复述代码；与代码不符（stale）；JSDoc/docstring 重复类型签名；填充语与装饰符 |
| **B** | 文档与事实不符 | 引用不存在的路径/命令/环境变量/符号；版本或数字快照；承诺未实现的能力 |
| **C** | 死代码与未使用 | 未被引用的导出/函数/类；未使用参数或 import；不可达分支；无人使用的兼容层与 re-export |
| **D** | 冗余抽象与过度防御 | 只有一个实现的接口；纯转发包装；类型系统已保证的重复校验；吞掉异常或只重抛的 try/catch |
| **E** | 重复实现 | 近似重复的函数块；同一字面量散落多份；Python 与 TS 对同一规则各写一份且已分叉 |
| **F** | 测试伪强度 | 无断言或恒真断言；断言实现细节；以快照替代行为断言；把被测量逻辑本身 mock 掉；遗留 skip/todo |
| **G** | 错误处理与日志 | 错误被降级为静默返回或普通日志；日志噪音；同一层内错误契约不一致 |
| **H** | 结构与命名 | 命名不承载信息或与行为不符；单文件混合多重职责；循环依赖；认知复杂度或参数过多 |
| **I** | 占位与伪功能 | 无期限 TODO/FIXME；看起来能用的假数据 stub；恒为假的开关；空实现 |
| **J** | 生成特征（元信号） | 极端模板化的对称结构；注释风格突变；"comprehensive/robust/seamless" 类空词；过度标题与 emoji |
| **K** | 配置与脚本 | 重复配置；未使用的依赖或环境变量；无人调用的 npm script；配置默认值与代码不一致 |

**严重度**（决定是否修，不决定是否记录）：

- **P1** 影响正确性、安全或对外契约——例如文档承诺了不存在的命令、错误契约不一致、恒真的测试掩盖了未验证行为。
- **P2** 影响维护与判断成本——例如死代码、重复实现、失真注释。
- **P3** 噪音——例如填充词、装饰符、命名偏好。

J 类**不作为独立缺陷**：它只是线索，必须落到 A/B/D/H 中的具体一条才有意义，否则就变成了对风格的攻击。

## 3. 本项目的「禁止标记」清单

以下模式看起来像 slop，实际是硬要求。**误报它们会直接损害安全边界**，因此固定不标记：

- guardrails 的 TTL、容量上限、单 key 长度/字符集、单 Session 历史上限、请求体上限与字段白名单。
- 服务端生成 Session 与 Cookie 属性（HttpOnly/SameSite/Secure）、可信代理 IP 判定（`TRUSTED_PROXY_IPS` 未配置时不采信 `x-forwarded-for`）。
- TLS 校验（`rejectUnauthorized`、`sslmode=verify-full`）与 `preflight` 的 production 通则。
- Python 侧 Pydantic `response_model` 与响应校验；TS 侧手写解析器（替代 `as T`）。
- 结账重新读取价格与库存、幂等键、事务边界与回滚、订单价格快照。
- `MockPaymentProvider` 与"支付未开放"提示（MVP 有意为之）。
- 双层 repository 薄壳（ADR 0002）、共享领域层 `src/domain`（ADR 0005）、幂等建表 DDL（ADR 0003）。
- demo 种子数据与占位商品内容。

**判据**：在 `AGENTS.md` 的边界章节或 `docs/adr/` 中有明确依据的模式，一律不标记；若确实认为某条边界本身有问题，单独作为"边界质疑"提出，不混进 slop 清单。

## 5. 每类的检测手段与工具就绪状态

| 类别 | 机械可判定的部分 | 必须靠判断的部分 |
| --- | --- | --- |
| A | 注释与相邻代码标识符重合度、JSDoc 与签名重复、装饰符/填充词表 | 注释是否与代码**不符**（关键，也最难） |
| B | 路径/命令/环境变量/符号是否存在；版本号与数字快照 | 承诺是否与实现一致 |
| C | 未使用导出与 import、未使用参数、不可达分支、未使用依赖 | 兼容层是否仍在被外部使用 |
| D | 单实现接口、纯转发函数、catch 体为空或仅重抛 | 校验是否已由上游保证 |
| E | 阈值化重复块、重复字面量 | 重复是否应合并（有时重复是正确的） |
| F | 每个测试的断言数、恒真断言、skip/todo、mock 覆盖率 | 断言是否真的在测行为 |
| G | 空 catch、错误被降级、日志密度 | 错误契约一致性 |
| H | 复杂度、参数个数、导入图环 | 命名与职责 |
| I | TODO/FIXME 无 issue、空实现、恒假开关 | stub 是否伪装成可用 |
| K | 依赖与环境变量引用计数、script 调用方 | 默认值是否与代码一致 |

**已验证的工具就绪状态**（不是假设）：

| 手段 | 状态 | 说明 |
| --- | --- | --- |
| `rg` | ✅ 15.2.0 | 文本与多行检索 |
| `node` + `typescript` | ✅ 24.18.0 / 5.9.3 | **Compiler API 可用**，可自研零依赖 TS AST 扫描器 |
| `python3` + stdlib `ast` | ✅ 3.14.2 | 可自研零依赖 Python AST 扫描器（无需 venv） |
| `jq` | ✅ 1.7.1 | JSON 结果处理 |
| pi-lens AST 工具 | ✅ 工具形式 | `ast_grep_search` / `ast_grep_replace`，**非 CLI** |
| `sg` / `semgrep` CLI | ❌ 未安装 | 不要假设可用 |
| `npx` 一次性工具 | ⚠️ registry 可达 | `jscpd` 5.4.1、`knip` 6.41.0、`ts-prune` 0.10.3；会改动 npm 缓存但不改 `package.json` |
| Python `vulture` | ⚠️ 陷阱 | **npm 上的 `vulture` 与此无关**；本机无 venv，Python 侧应走 stdlib `ast` |

结论：**确定性检查可以完全零新增依赖地自研**（TS 用 Compiler API、Python 用 stdlib `ast`），这与仓库"不随意引入重依赖"的约束一致，也让结果将来能在 CI 复现。

## 6. 证据格式与误报政策

每条发现必须包含：

```text
位置        文件:行（或符号名；行号会漂移，符号名是主键）
原文        逐字引用
判据        第 2 节的编号 + 第 1 节定义的哪个条件被违反
受损方      删掉它，谁受损？（答不出就不算 slop）
证据强度    机械判定 / 需人工确认
复核方式    可重跑的命令或检查点
```

**不接受**：仅凭风格的结论；把"我不喜欢这个写法"写成缺陷；把第 3 节的禁止标记清单里的模式报成 slop。

结果落地两种形态：**JSONL**（可统计、可 diff、可跨会话续跑）+ **Markdown 报告**（可读、可评审）。快照与统计只出现在带日期的报告里，不写进常驻文档。

## 7. 三条扫描路线（待你选择）

| 路线 | 做法 | 成本 | 可信度 | 可复用 |
| --- | --- | --- | --- | --- |
| **1. 机械优先** | 先自研零依赖扫描器覆盖 A/B/C/D/E/F/G/K 的可判定部分，再把不可判定的交给人工 | 中（一次性写扫描器） | 高（确定性发现可复现） | 高，可直接变成常驻门禁 |
| **2. 工具优先** | `npx jscpd` / `knip` / `ts-prune` + `eslint-plugin-sonarjs` | 低 | 中（外部工具口径需校准） | 中，依赖外部工具与版本 |
| **3. 判断优先** | 按第 4 节切块，逐块人工/模型审阅 | 高（34k 行） | 依赖评审者一致性 | 低，结论不可重跑 |

三者不互斥。已识别的组合倾向：**路线 1 打底（确定性部分）+ 路线 3 补判断部分**，路线 2 用于交叉验证重复率与死代码两个易错的类别。

## 8. 审计期间不改代码

准备与扫描阶段**只产出发现，不改任何行为**。确认后按类别分批修复，每批独立可回滚、独立验证；修复顺序优先 P1，且不得为了让指标好看而删除第 3 节清单中的边界校验。
