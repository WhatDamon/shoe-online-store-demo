# i18n 阶段 2（加入 zh-CN）实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 让站点真正支持中文——`zh-CN` 界面文案全量落地、可在 AppBar 切换、AI 与错误提示按语言响应，并且**未翻译的内容绝不发出假的 SEO 信号**。

**架构：** 在阶段 1 已建成的 `src/i18n`（纯层）+ `src/components/i18n`（React 适配器）+ `src/app/[locale]` 路由骨架上，把 `zh-CN` 加入 `LOCALES`，补一份键集完全一致的 `zh-CN` 词典；新增原生的「可用语言」判定（`src/i18n/content.ts` 纯词汇 + `src/lib/blog.ts` 的 IO），让 canonical/hreflang/sitemap 按**实际存在的译文**决定，而不是按 `LOCALES` 展开。语言与市场继续解耦：中文界面仍然显示 `US 8.5` 与 `$128.00`。

**技术栈：** 无新增依赖。TypeScript + Next.js App Router + React，手写类型化词典，`Intl`（`NumberFormat` / `DateTimeFormat` / `PluralRules`）。原生 `button`/`a` + 既有 `src/proxy.ts` 的 cookie 持久化。

**规格：** `docs/superpowers/specs/2026-10-13-i18n-multi-language-design.md`（§6 词典机制、§7 语言/市场解耦与格式化收口、§8 SEO 与内容回退、§9 AI/防护/后端边界、§10 门禁与测试、§11 阶段 2）。**ADR：** `docs/adr/0008-locale-routing-and-typed-dictionaries.md`。

## 全局约束

（每个任务的要求都隐含包含本节。）

- **语言集合的单一来源是 `src/i18n/locales.ts` 的 `LOCALES`。** `zh-CN` 加入后，`messages.ts` 的 `DICTIONARIES` 缺少对应词典是 **TS2741 编译错误**——这是设计意图，不要用 `as` 绕过。
- **★ 每个任务只要往 `en.ts` 加一个键，就必须在同一个任务里给 `zh-CN.ts` 补上同名的中文值。**
  因为 `Messages = Record<keyof typeof en, string>`，加键后 `zh-CN.ts` 少这一条就是 **TS2741**——中间态不可提交。
  因此**任务 2、3、5、7、9 的文件清单都必须包含 `src/i18n/dictionaries/zh-CN.ts`**（本计划已列全，执行时不要漏）。
  反向也成立：**不要**给 `zh-CN.ts` 加 `en.ts` 里没有的键（键集必须双向一致）。
- **语言与市场解耦（ADR 0008 决策 6，不可协商）**：`SITE_MARKET` / 货币 / 尺码体系决定**尺码与价格**，语言只决定**文案**。中文界面下 `US 8.5`（尺码）与 `$128.00`（价格）**保持不变**。不要在阶段 2 引入「中文就显示 EU 码或人民币」。
- **词典只装展示文案**：不得携带价格、库存、订单状态、尺码体系、货号、色名等交易事实（ADR 0004）。**输入解析规则**（`OFF_TOPIC` 词表、`parseSizeHint` 正则、`estTokens` 比率）**不进词典**，它们留在 `src/domain`/`src/server` 作为行为规则。
- **`src/i18n` 是纯层**：无 React、无 `src/server/**`、无 `src/db`、无 IO、无 `process.env`。React 适配器只能住 `src/components/i18n/`。
- **服务端读取 locale 只能来自 `params`**（经 `isLocale` 收窄）。**禁止 `next/root-params`**（在 vitest 下抛错且不可测），**禁止 `as Locale` 强转**。
- **Route Handler 无法从 `[locale]` 读 locale**，只能经请求体/请求头/cookie，且**必须 `isLocale` 校验**。
- **18 个受保护测试文件必须保持不改动且全绿**：它们不挂 `LocaleProvider`，靠 `src/components/i18n/locale-provider.tsx:17` 的 `DEFAULT_VALUE`（`DEFAULT_LOCALE = 'en'`）拿到英文。新增语言断言一律写**新文件**（R22：允许纯新增断言，**禁止**修改/删除/放宽任何既有断言）。
  - **窄例外（R35）**：**期望值本身就是语言集合 / 语言列表 / 语言键集合**的既有断言，由**改变语言集合的那个任务**同步更新（任务 1）。边界很窄，不要把这条读成对别的断言的许可。
- **未翻译的内容不得发出假 SEO 信号**：回退页 canonical 指向默认语言 URL、**不发 hreflang**、**不进 sitemap**。有 `noindex` 意图的页面不要靠 canonical 兜底。
- **零新依赖。** 不改 `next.config.ts`、不改 `vitest.config.mts`、不改 `src/proxy.ts` 的 matcher 字符串。
- **中文文案必须是人工质量**：不得机翻痕迹（"请查收" 式套话、逐词直译）。术语按下面《术语表》统一。专有名词（`Evoloop`、商品名 `Urban Bloom`、`little buddy`、`Geist`）**不译**。
- **每次 commit 只暂存本任务文件**，**禁止 `git add -A` / `git add .`**——工作区可能有他人未提交的文档。
- 提交信息用 `feat(i18n): …` / `test(i18n): …` / `fix(i18n): …` / `docs(i18n): …`。

## 审查重点（Review Focus）

1. **未译内容绝不能发出 hreflang / 进 zh-CN sitemap。** 假 alternate 比没有 alternate 更伤——它会让搜索引擎把英文页当成中文页收录。**测试**：任务 5、任务 6 各含一条「未译 slug 的 alternates 不含 `zh-CN` 且 sitemap 不含该 URL」的断言。
2. **畸形/恶意语言输入不得 500、不得回显。** cookie 被改成 `../..`、`zh-CN'`、超长串；`Accept-Language: zh-CN;q=abc`、空串、`*`、超长头。**测试**：任务 1（negotiation）与任务 2（cookie）各含边界用例，断言回落到默认语言且响应体不回显输入。
3. **中文 token 估算不得低估到能穿透 AI 日预算。** `estTokens` 若继续按 `len/4` 算中文，`AI_DAILY_TOKEN_CAP` 会被 3–4 倍穿透（成本/滥用边界）。**测试**：任务 8 含「纯中文文本的 estTokens ≥ 其字符数」与中英混合的断言，并有一条预算用例。
4. **语言切换不得丢上下文、不得造成双重前缀或重定向环。** 在 `/zh-CN/shop` 切 EN 必须到 `/en/shop`（不是 `/en/zh-CN/shop`）；在 `/en` 切 zh-CN 必须到 `/zh-CN`；连续切换幂等。**测试**：任务 2 含 `stripLocale`/`localePath` 往返断言与切换器 href 逐字断言。
5. **缺键必须编译或测试失败，绝不渲染 `undefined`。** 两个词典的键集必须**双向**完全一致——`satisfies` 只保证一个方向，另一方向只有运行期相等断言能抓（阶段 1 遗留盲点）。**测试**：任务 1 把键集断言改成**遍历 `LOCALES`**。
